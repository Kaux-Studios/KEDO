KEDO 1.0.0-alpha.1 — primera prerelease del lenguaje 1 y su toolchain. Sin garantía de compatibilidad entre alphas; la garantía de SemVer empieza en 1.0.0 ([ADR-0001](https://github.com/Kaux-Studios/KEDO/blob/main/spec/adr/0001-versionado-semver.md)).

**Paquetes** (GitHub Packages de Kaux-Studios, también adjuntos a esta release): `Kedo.Core` (valores, diagnósticos, esquema, lector del pack, VM determinista), `Kedo.Compiler` (lexer, parser, formateador, resolver, esquema como dato, compilador de comportamientos, escritor del pack, importador JSON) y la herramienta `kedo` (`dotnet tool`: `parse | check | resolve | explain | catalog | compile | build | schema | fmt | import-json | mcp`, todo con `--json`). Restaurar desde GitHub Packages pide un token con `read:packages` aunque el paquete sea público.

**Lenguaje:** spec v0.1 (gramática, resolución en capas, mixins, componentes, borrado explícito, procedencia y `explain`), esquemas escritos en KEDO, hooks y funciones compilados a una VM de registros con frames guardables, KEDO Pack binario (formato 2). Novedades de esta tanda:

- Decimales de punto fijo como datos ([ADR-0008](https://github.com/Kaux-Studios/KEDO/blob/main/spec/adr/0008-decimales-de-punto-fijo.md)).
- Mapas con claves libres o de un enum, claves entre comillas y restricciones `min_items`, `max_items`, `min_length`, `max_length`, `one_of` ([ADR-0009](https://github.com/Kaux-Studios/KEDO/blob/main/spec/adr/0009-mapas-y-restricciones-de-esquema.md)).
- Advertencias K3014/K3015 cuando `=` mezcla en silencio con lo heredado, `explain` por elemento, un diagnóstico por valor escrito y orden de declaración en la API ([ADR-0010](https://github.com/Kaux-Studios/KEDO/blob/main/spec/adr/0010-diagnosticos-de-mezcla-y-orden-de-declaracion.md)).

**Herramientas para agentes:** servidor MCP (`kedo mcp`), skills `kedo-syntax`, `kedo-author-content` y `kedo-toolchain`, y el addon de Godot en `addons/kedo`.

**Pendiente antes de 1.0.0:** completar `PublicAPI.Shipped.txt` y volver RS0016/RS0017 a error, fijar la línea base de package validation, decidir el feed para consumir sin token (#18), formularios generados desde el esquema (#14), resolución incremental (#15) y carga del pack bajo demanda (#16).
